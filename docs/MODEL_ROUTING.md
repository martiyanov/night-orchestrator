# Маршрутизация моделей

Роли (config/routing.json), не вендоры:

| Роль | Назначение |
|---|---|
| explorer | дешёвое быстрое чтение/локализация/минимальное воспроизведение |
| implementer | красный тест → минимальная правка → целевые тесты |
| strong_finalizer | сильнейшая доступная; ОДНА ограниченная попытка, только после доказанного прогресса (или после исчерпания reasoning-лимита) |
| reviewer | рецензия диффа/тестов; желательно другой вендор |

- **Назначение модели роли**: `roles.<role>.model = provider/model-id`.
- **Добавление поставщика**: case-блок в `bin/model_call.sh` (базовый URL +
  источник ключа) — ключи никогда не логируются. Поддерживаются любые
  OpenAI-совместимые провайдеры; примеры конфигурации: Z.AI, OpenAI.
- **Резервная модель** (`fallback`) включается при сбое провайдера той же роли.
- **Эскалация по прогрессу**: explorer без прогресса → implementer;
  implementer не конвергирует после прогресса → одна strong-попытка;
  исчерпание reasoning-лимита → повышенный лимит → strong-модель → BLOCKED.
- **Экономика**: дорогие ступени — только по событию; обычный путь дешёвый.

Доказательства вызовов (модель, латентность, размеры) — в
`runs/<id>/<task>/model_calls.jsonl`; без текстов промптов и ключей.
