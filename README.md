# Night Orchestrator

**Локальный оркестратор для безопасной автономной работы LLM над программными
проектами.** Вы описываете задачу — он делает её в изолированной копии
репозитория, под детерминированными ограничениями, и возвращает проверенный
результат. Слить в основную ветку или задеплоить можно только с вашего
явного разрешения.

## Какую проблему решает

Обычный coding-агент с полным доступом к машине — это риск: одна ошибка или
уговоренная модель, и он правит не то, не там, или выполняет опасную команду.
Night Orchestrator ставит исполнение в рамку:

- работает **только в одноразовом Git worktree** задачи, не в вашем чекауте;
- **запрещает командам** push/merge/deploy, docker/systemctl, сеть, доступ к
  секретам и production-каталогам — запреты в shell-коде, не в промптах;
- ведёт **модели по ролям** (дешёвый исследователь → исполнитель → сильный
  финализатор → рецензент) с бюджетами времени и чтения;
- всегда заканчивает **машинным результатом** (RESULT) и человеческим
  отчётом вам;
- перед любым повышением риска ждёт вас: **OWNER PASS** (принять код) и
  **OWNER GO** (разрешить deploy) — отдельных автоматических путей нет.

Production по умолчанию недоступен моделям вообще (guard-корни проекта).

## Быстрый старт

Зависимости: bash, git, jq, python3. Всё остальное — локально.

```bash
git clone <репозиторий> && cd night-orchestrator

# 1) установка в свой каталог (конфиги создаются из примеров)
./scripts/install.sh --target ~/.local/share/night-orchestrator

# 2) проверка окружения
./scripts/doctor.sh --root ~/.local/share/night-orchestrator

# 3) описать свой проект в config/projects.json (репозиторий, worktrees,
#    запретные пути; образец — config/projects.example.json)

# 4) самопроверка без ключей и внешних моделей
cd ~/.local/share/night-orchestrator && ./bin/selftest.sh --full

# 5) первая безопасная задача (read-only, мок-модели):
#    см. docs/INSTALLATION.md и examples/TASK.example.json
```

Полная документация — в `docs/`: INSTALLATION, CONFIGURATION, SAFETY_MODEL,
MODEL_ROUTING, EXECUTION_LIFECYCLE, INTAKE_GATE, OPERATIONS.

## Что внутри

```
задача (TASK или сообщение обычным языком через Intake)
→ task worktree → гейты → модели по ролям → проверки
→ RESULT → отчёт владельцу → [OWNER PASS → merge] [OWNER GO → deploy]
```
