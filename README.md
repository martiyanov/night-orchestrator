# Night Orchestrator

Локальный оркестратор для безопасной автономной работы LLM над программными
проектами.

Он:
- принимает формализованную задачу (TASK) или сообщение обычным языком (Intake);
- создаёт изолированный Git worktree для каждой задачи;
- разрешает моделям работать только в заданных границах (детерминированные
  safety-гейты в shell-коде, не в промптах);
- управляет выбором моделей по ролям (исследователь → исполнитель → сильный
  исполнитель → рецензент) с бюджетами и эскалацией;
- запускает проверки и целевые тесты;
- формирует машинно-читаемый результат (RESULT) и человеческий отчёт;
- останавливается перед merge/push/deploy, оставляя решение владельцу
  (OWNER PASS / OWNER GO).

## Быстрый взгляд

```
задача (TASK / Intake) → task worktree → гейты → модели по ролям
  → проверки → RESULT → отчёт владельцу → [OWNER PASS → merge] [OWNER GO → deploy]
```

## Установка за 3 шага

```bash
./scripts/install.sh --target ~/.local/share/night-orchestrator   # скопирует и создаст конфиги из example
$EDITOR .../config/projects.example.json → projects.json           # ваш проект
./scripts/doctor.sh --root ...                                      # проверка окружения
```

Подробности: `docs/INSTALLATION.md`, `docs/CONFIGURATION.md`.

## Самопроверка без секретов и внешних моделей

```bash
./bin/selftest.sh          # ~300 проверок: гейты, бюджеты, RESULT, отчёты, Intake
./bin/selftest.sh --full   # + сценарии исполнения на моках моделей
```

## Безопасность — коротко

- работа только в task-worktree; запретные пути проекта недоступны из команд;
- push/merge/deploy/docker/systemctl/сеть/секреты — запрещены гейтами;
- любые RECORD-подобные действия — только через владельца;
- бюджеты: turns, время, чтение-до-записи, лимит рассуждения (reasoning
  budget), финализация результата.

Полная модель: `docs/SAFETY_MODEL.md`. Архитектура: `docs/ARCHITECTURE.md`.
Решения и их причины: `docs/ADR/`.
